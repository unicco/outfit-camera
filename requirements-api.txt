# Backend dependencies for coordinate-recorder
# Issue #40: Database and automation features
#
# 版は `==` で固定する（`>=` に戻さない）。
# このファイルは CI（ci-lint-check / test / dependency-check）と本番 VPS
# （deploy/setup-vps.sh の `pip install -r`）の両方が読む。`>=` だと解決結果が実行時期で
# 変わり、CI と本番がメジャー単位でズレる（＝CI green が本番の動作を保証しなくなる）。
# 本番 venv は「既存が条件を満たせば据え置く」pip の挙動で古い版が残り続ける一方、
# venv を作り直した瞬間に全パッケージが最新へ飛ぶ。この落差が無検証の本番メジャー更新になる。
#
# ピン値の基準:
#   1. 原則は本番 VPS venv の実測値（`pip freeze`）。本番と一致させることで、この
#      ファイルの変更が起動する自動デプロイが pip の no-op で安全に着地する。
#   2. 例外として、pip-audit が既知脆弱性を報告するパッケージは修正版に上げる。ただし
#      「その時点の最新」ではなく **CI で稼働実績のある版** を採る（下の ★ 印）。
#      本番実測値をそのまま採ると、既知脆弱性を意図的に固定することになるため。
#      推移的依存でもここに書く。書かないと pip の「既存が条件を満たせば据え置く」挙動で
#      本番だけ脆弱な版が残り続ける（CI は無ピンで最新を解決するので気づけない）。
# 更新は Dependabot の PR 経由で 1 つずつレビューして上げる（major は個別 PR になる）。
